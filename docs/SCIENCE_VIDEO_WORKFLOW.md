# 一键科普视频生成工作流

本文档是项目 Agent 的执行规范。实现参考 `ai-science-video-maker` 中的叙事、视觉、来源与本地制作原则，并按 FrameCraft 的 DeepSeek、阿里云语音、HyperFrames 和用户本地渲染架构重新实现。

## 1. 三种输入模式

### 主题模式

用户提供主题、受众和额外要求。DeepSeek 生成科普讲稿、章节、每章视觉主张、语义动画类型和来源候选。只有可公开访问的 HTTPS 来源进入 `SOURCE_LEDGER.md`。通过验证仅代表链接可访问，内容 Agent 仍需检查来源与表述是否对应。

### 文案模式

用户文案是唯一内容原文。系统可以按标点拆成 TTS 和分镜片段，不得改写、概括、补充或重新排序。阿里云 TTS 生成旁白；字幕必须完整覆盖原文。

### 媒体模式

用户上传音频或视频。视频只提取原音轨，阿里云 ASR 生成逐字稿。最终成片必须使用原音频，不能用 TTS 重配。ASR 文本只服务于字幕和视觉设计。

## 2. 内容与来源

1. 一章只解释一个核心概念，并给出一句可视化主张。
2. 精确数字、研究结论和机构口径必须关联来源编号。
3. 无法可靠核对的数据改用定性表达，不生成看似准确的虚构刻度。
4. 来源短注放在相关画面的左下方、字幕安全区上方。
5. 观众画面禁止出现“场景、制作、动画、工作流、Agent、FrameCraft”等幕后词汇。
6. 文案尽量避免使用“不是……而是……”句式。

## 3. 语义动画分类

每场选择一个主导语义运动，不能只更换标题后复用同一块面板。

| 类型 | 适合内容 | 主动画 |
| --- | --- | --- |
| `mechanism` | 因果、传播、形成过程 | 粒子或信号沿路径依次穿过节点 |
| `scale` | 大小、距离、强弱、范围 | 同心尺度场、层级缩放和相对距离 |
| `comparison` | 两类对象或条件差异 | 双侧对照、共同基准和差异显现 |
| `timeline` | 演化、周期、历史过程 | 曲线或轨道上的节点逐个推进 |
| `system` | 组成、关系、生态或网络 | 中心概念与外围节点动态连接 |

每个关键元素都要有入场、持续运动和退场。流程节点必须逐个出现。持续运动应表达含义，例如粒子传播、轨道运转、尺度呼吸或状态迁移，不能只做无目的漂浮。

## 4. 画面规则

- 字幕使用简体中文，固定居中放在底部安全区，并有短促渐入渐出。
- 主视觉应占据足够面积，避免大片无意义空白，也不能压住字幕和来源。
- 圆角必须由真实 `border-radius` 实现；底板优先半透明，不默认给每个元素加实色方框。
- 相邻分镜改变空间结构、视觉焦点或运动方向，不能形成连续 PPT 页面。
- 一秒内应能辨认本场科学焦点；屏幕文字只承担标题、短标签和关键关系，完整解释交给旁白。
- 16:9 与 9:16 分别布局，不能把横版机械缩放成竖版。

## 5. Agent 与工程产物

每个项目拥有独立 Agent 上下文、素材目录、聊天记录和版本目录。openJiuwen 并行调度内容、视觉、时序专家，DeepSeek Pro 代码总监生成当前项目的唯一创意规格。通用编译器负责把规格写成独立 HyperFrames HTML 工程，不携带上一项目的文字或布局决定。

必须产出：

- `analysis/analysis.json`
- `analysis/edit_plan.json`
- `analysis/creative_plan.json`
- `analysis/agent_trace.json`
- `input/scene_seed.json`
- `input/transcribe/transcript.json`
- `input/SOURCE_LEDGER.md`（主题模式）
- `<version>/timeline.json`
- `<version>/subtitles.srt`
- `<version>/hyperframes/`
- `<version>/hyperframes_project.zip`
- `<version>/agent_visual_review.json`

## 6. 渲染与验收

1. 服务端 Agent 生成可复渲染工程包，不保存 MP4。
2. 用户电脑的 Renderer 调用 HyperFrames `--strict` 真实渲染。
3. 本机 `ffprobe` 检查音视频流、分辨率和完整时长。
4. 本机从全片等间隔抽取八帧形成临时联系表。
5. 视觉 Agent 对照真实分镜起止时间检查构图、语义、文字、字幕、来源与场景差异。
6. 同一长分镜可能贡献多张连续截图，验收时不能误判为两个分镜重复。
7. 评分低于 75 或存在硬伤时保留失败原因，不登记为通过版本；修改工程后重新真实渲染和验收。
8. 联系表验收后删除，MP4 只保留在用户电脑。

项目不提供 FFmpeg 静态合成、复制旧成片或伪造 Agent 成功的兜底路径。
